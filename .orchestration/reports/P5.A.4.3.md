# P5.A.4.3 Offline banner and crash-report opt-in

Branch `agent/senior/P5.A.4.3` @ b790018, stacked on `agent/senior/P5.A.4.2` @ 825389f. Merge order: FIX-mobile-root-wiring, P5.A.4.1, P5.A.4.2, then this branch.

## What changed

- **Telemetry**
  - `src/telemetry/consent.ts` reads and writes the `hexascore.crashConsent` preference (`unset | granted | denied`) on the `expo-sqlite/kv-store` port. Any unknown value reads as `unset`, so consent defaults to off.
  - `src/telemetry/crash.ts` defines four things:
    - `buildCrashReport` builds exactly `{appVersion, versionCode, androidApi, screen, message, stack}`. E-mails become `[email]`, and `hx_…` tokens and `Bearer …` become `[token]`. The stack is capped at 8,192 UTF-8 bytes and the message at 1,000 runes, to match the server limits in `app/appapi/telemetry.go`. The screen is capped at 200 runes and has its query string removed, because the server rejects `?`.
    - `createCrashReporter` does nothing unless consent is `granted`, and never throws.
    - `installGlobalHandler` wraps React Native's existing global error handler: it reports the error, then passes it on, so the red box and the native crash still happen. It also restores the previous handler on uninstall.
  - `src/telemetry/runtime.ts` wires the reporter to the generated `clientErrors` call through a dedicated `createClient` that sends only `X-App-Version`, with no `Authorization` header (anonymous). It reads `appVersion` and `versionCode` from `expo-constants` and `androidApi` from `Platform.Version`, and installs the global handler when `ErrorUtils` exists.
  - `src/telemetry/CrashConsentPrompt.tsx` is the first-launch prompt, with "Don't send" and "Send reports" buttons, each with a 44 dp target.
- **Offline banner**: `src/platform/OfflineBanner.tsx` uses `useSyncExternalStore` on `src/platform/network.ts`. It shows only while the state is `offline`, because `unknown` counts as online, the same rule as P5.A.4.1. It is a polite live region.
- **Root layout** (`app/_layout.tsx`)
  - It exports an Expo Router `ErrorBoundary`. The boundary reports the error and shows `errors.serverTitle` with an `errors.retry` button, both existing keys.
  - It renders the banner, and the prompt while consent is `unset`.
  - It tracks the screen from `useSegments()`. That gives route patterns such as `/[type]/[slug]`, never concrete values, so no username reaches a report.
- **i18n**: new keys `account.offline` and `account.crashReports.{title,body,allow,deny}`, added in en, pt-BR and es in `resources/lang/*.json`, then `bun run --cwd apps/mobile catalogues`.
- **Nav test**: `src/navigation.test.tsx` gains `useSegments: () => []` in its `expo-router` mock.

No new dependency and no third-party service. SDD 10 §7.7 and ROADMAP say native capture (Sentry or similar) needs an ADR, and ADR 0019 / Q-B1 approve no telemetry package. Reports go only to our own `POST /app/v1/client-errors` (P3.C.4.1, 204).

SDD: 10 §7.3 (offline banner via `src/platform/`), §7.7, §5 (preferences row); SDD 05 §6.4 (`reportClientError` contract); SDD 12 §6.4 / FR-12-7.

## Limits

- The Settings toggle that revokes consent belongs to P5.B.4.2 (`src/profile/Settings.tsx`). It needs only `setCrashConsent(false)` from `src/telemetry/runtime.ts`, and the reporter reads consent at every report. Until then, consent can be revoked only by clearing app data.
- `versionCode` is the static `expo.android.versionCode`. EAS remote `autoIncrement` values need `expo-application`, which is not approved, so the code is marked `shortcut:`. The server discards `versionCode` anyway (SDD 12 §5).
- `useSegments` is cast because the repo does not generate the typed-routes manifest, so the hook is typed `never`.
- `resources/lang/*.json` is also touched by my other branches in review (community rows). They add different keys, so any conflict is textual only; re-run `catalogues` after merging.
- No device run (owner-gated).
