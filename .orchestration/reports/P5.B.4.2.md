## Design

- The locale is now a small store, `createLocaleStore` in `src/i18n/locale.ts` (`get`/`set`/`subscribe`):
  - `appLocale` in `auth/runtime.ts` is that store;
  - `_layout.tsx` subscribes to it with `useSyncExternalStore` and feeds `LocaleProvider`, so every screen re-renders;
  - the API client takes `locale: () => AppLocale` and reads it per request, so `Accept-Language` follows the change.

  `set` writes the override through the existing `writeLocaleOverride`.
- On the profile tab, `onLocale` switches the UI first and then sends `PATCH /me {locale}`. If the PATCH fails, the device keeps the override and the generic error shows; the server value catches up on the next save.
- `PATCH /me` requires every field (zod shape in `me.go`), so `patchBody` merges the change over the loaded profile. `username` is sent only while it is still unset. The server keeps it once, so the field turns read-only after that.
- `parseMe` and `parseDevices` narrow at the boundary. The generated client types `GET /me` and `GET /tokens` as `unknown`, because those routes are untyped `g.Get`. A typed response schema would mean moving them to `api.Register` and regenerating `app-v1.json` and `api.ts`. That is not needed for this row, so it is left out.
- Revoking the current device signs out locally even if the DELETE fails, the same as logout: the local wipe protects the user.
- The crash-report revoke toggle is impl-mobile's `CrashReportSwitch` (`setCrashConsent(next)`), unchanged. It sits in the Privacy slot next to the new personalisation switch (D-29).
- The `wipeUserData` comment in `auth/runtime.ts` is shortened to one line.
- `settingsWire.test.tsx` now wraps the tab in a `QueryClientProvider`. In the app, the root `PersistQueryClientProvider` supplies it.
