status: concluida

red: `go test ./internal/ingest/httpx -run TestRetryAfterPause` (new `Config.Timeout` = 100 ms, a 429 with Retry-After 120 whose pause takes real time in the test clock) → `context deadline exceeded (Client.Timeout exceeded while awaiting headers), calls = 1`.
green: `go test ./internal/ingest/httpx -count=1` → ok (TestRetryAfterPauseDoesNotEatTheRequestTimeout: 200 after one pause, 2 calls; TestEachAttemptStillHasADeadline: a hung server still ends with DeadlineExceeded after the attempt timeout); `go test -tags integration ./tests/ingest -run 'TestSecurity|TestFetchOutage|TestWiring'` ok; golangci-lint 0 issues.
design: the JSON and Image clients have no `http.Client.Timeout` any more (the Safe client keeps its 60 s dial, TLS and response-header timeouts). `send` wraps each attempt in `context.WithTimeout(ctx, 60 s)` after the throttle wait and the in-flight slot, and cancels it when the body is closed (same release hook as the slot), so the deadline covers send, headers and body read of that attempt only. `Config.Timeout` (tests) overrides the 60 s.
changelog: Fixed: an ingestion request no longer fails when the server asks to wait (Retry-After) for more than about a minute.
roadmap: no box
risks / follow-ups: the whole request is now bounded only by the caller's context (5 attempts x (60 s + up to 300 s pause)); the run budget (5 min per job) and the queue job timeout bound it in practice. A per-attempt timeout is still not retried (unchanged).
