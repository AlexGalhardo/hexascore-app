## Design

- Queue runtime (`src/rating/runtime.ts`):
  - `createRatingRuntime` builds the store, the cache and the drain. `onResult` goes to `cache.onResult`, plus a toast for the `rating` lane.
  - `enqueue` is bound to the current user and answers `null` when there is no user, which the sheet shows as "not saved".
  - `auth/runtime.ts` wires it with `sendEntry(appClient, …)`, `getNetworkState() !== "offline"`, `appClient.upgradeRequired()`, and `startQueue` on network and foreground. It is the recipe from P5.A.4.2.
- `followMe(session, meShow, setUser)`: every `active` state reads `GET /me`, then calls `observeMe` (deletion routing) and binds the queue to `me.id`. Any other state unbinds it.
- The queue is deliberately not cleared in `wipeUserData`, contrary to my previous handoff. SDD 10 §8 replays it for the same user after a 401 re-login, and the user binding discards it for another user (P5.A.4.2 report). A one-line `store.clear()` is available if the specialist prefers that.
- `/app/v1/me` `id` is a string, so a JS client never rounds an int64. `deletionScheduledAt` is read so that `observeMe` has something to route on. Scheduling deletion revokes the tokens, though, so in practice the app sees a 401 first.
- Category keys: `CATEGORY_KEYS` mirrors `app/scoring.CategoryKeys`, with a `shortcut:` comment. The `/app/v1` rating body is `unknown` in the OpenAPI, so the generated client has no enum. Labels come from `categories.<singular>.<key>`.
- Toasts use `ToastAndroid` in `toast.android.ts`, with a no-op `toast.ts` for Jest and tsc. Biome's `useReactNativePlatformComponents` asks for exactly that split.

## Risks / follow-ups

- Proposed row: give the `/app/v1` rating PUT body a schema (`scores` keyed by an enum per type), so the client generates the keys and `categories.ts` can go.
- The sheet's visuals (spacing, modal chrome) are basic components; the restyle belongs to impl-mobile (IMPL-mobile-v1-item).
- A queued write from before an app restart has no snapshot. Its rollback refetches `/me` and the item instead of restoring.
