risks / follow-ups:

- Design deviation from the ROADMAP note (BeforeSave + FOR UPDATE re-read in `app/admin/resources/*`): vukem v0.34 resource saves call `orm.Update`, which rewrites every model column, so a panel-writable `Item`/`Entity`/`Edition` resource would clobber a concurrent apply's `provenance`. The panel resources stay read-only; edits go through `POST /admin/catalog/{type}/{id}/fields`, which takes the same advisory + row lock as apply, reads `before` under that lock and writes through `catalog.WriteField`. SDD 04 §7.4 amended accordingly.
- Provenance of an admin-edited field is `hexascore` (SDD 01 licensing names it as a HexaScore source; it is in `DefaultCatalogAPISources`). `EnsureSource` inserts it on first use.
- Admin edits bypass `catalog_locks` (admins own locks). No `admin.AuditLog` row: this is not a vukem resource CRUD; `catalog_audit` is the record.
- Only the item manage page has the form; entity and edition edits use the same route (type `entity` / `edition`) and redirect to `/admin/catalog-audit` until those panel pages exist.
- Revert of an admin row reuses P4.B.2.4 `single` (source `admin` is revertible); not covered by a dedicated test.
