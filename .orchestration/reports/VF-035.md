# VF-035 report

- Status: PR open, see below. Branch `feat/vf-035-composite-keys`.
- ORM: `orm.CompositeKeyer` (`PrimaryKeys() []string`), `orm.PrimaryKeysOf[T]`, `orm.ErrKeyNotUnique`. `Update`/`Delete`/`ForceDelete`/`Restore` filter on every key column; a single-model write matching more than one row (the VF-035 mistake: `PrimaryKey() = "user_id"` on a composite table) returns `ErrKeyNotUnique`, rolled back inside `db.Tx` (`TestSecurity_A04_NonUniqueKeyWriteFails`). Single-key APIs (`Find`, `Chunk`, relations, `Attach`, `Reseal`, `Unique.Ignore`) return an error; `CursorPaginate` adds every key column; `admin.NewResource` panics on composite models.
- Schema: `t.SmallInteger`, `t.Primary(cols...)` / `Column.Primary()` (UUID and composite keys, Create only), `Column.StoredAs(expr)` (`GENERATED ALWAYS AS (expr) STORED`, all three dialects).
- Not done: ORM `generated` tag (VF-009; keep `db:"-"`).
- Docs: `docs/database.md`, `docs/security.md`, site `database/migrations.mdx` (Primary keys, Generated columns), `database/orm.mdx` (Composite primary keys).
- Release: none (Q-D-006). Adoption: replace `s.Raw` CREATE TABLE for `items`/`ratings` with `t.UUID("id").Primary()`, `t.SmallInteger`, `StoredAs`, `t.Primary("user_id","item_id")`; `Rating` model gets `PrimaryKeys()` and can use `orm.Update`/`orm.Delete`.
