## Design

- Both lanes already existed in the P5.A.4.2 queue: `QueueOp` `status`/`timeToBeat`, `sendEntry`, and `status-not-completed` in `CONFLICT_CODES`. This row only adds the UI and the cache.
- `createStatusCache` snapshots and restores only its own field of `/items/{id}/me`, never the whole object. This matters because the rating cache's snapshot restores the whole `me` object, and a field-level restore keeps a parallel rating rollback from clobbering a status write.
- On success, the field takes the server's value from the body (`status` or `timeToBeat`); a DELETE writes null. Any rollback or drop restores the snapshot and invalidates `itemMe`.
- Client-side rules are only the input bounds the note allows: 0.5–10,000 h in 0.5 steps, and at least one style (the server answers 422 `required` on `mainHours` otherwise). "Completed only" stays a server rule and comes back as a 409 rollback.
- `RatingQueue` keeps its name; it now carries every lane of the one offline queue. A rename would touch impl-mobile's files for no behaviour change.
