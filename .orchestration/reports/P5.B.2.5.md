## Design

- There is one query per type (`type=` filter), the same pattern as `HomeBody`. Each group shows the first page only.
- Each group's count is `entity.showing` ("{count} of {total}"), using `meta.total` when the server sends it.
- Known gaps:
  - **Cursor (load more).** `EntityPage` has no "next" slot, so I did not add UI to impl-mobile's presentational page. Wiring it is `useInfiniteQuery` plus `meta.next_cursor`, once impl-mobile adds an `onMore`/`hasMore` prop per group. I suggest an IMPL-mobile row for that.
  - **Role chips.** The API exposes `role=` but no per-role counts, and `EntityPage` needs counts for its chips. `roles={[]}` hides them.
  - **Covers.** `coverUri` is null: `ItemJSON` on main has no `coverThumbUrl` until FIX-app-item-cover-urls merges. After that merge, it is one line in `rowOf`.
- The empty-state action is `errors.home` ("Back to home") and navigates to `/`; its body is empty because no body string exists.
