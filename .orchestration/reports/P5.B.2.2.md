## Design

- `StarInput` is not a second input: it renders impl-mobile's `RatingInput` and only wraps `onChange` (no-op on the same value, one selection haptic per change). Every gesture and the TalkBack adjustable control stay in `src/ui`.
- `createRatingCache(queryClient)` is the single place that touches the cache for the `rating` lane: `optimistic`, `restore`, and `onResult` (the drain's `onResult`). Snapshots are keyed by item, and only the first pending write's snapshot is kept, because the queue replaces an older queued write of the same item and lane, so the first snapshot is the real "before". With no snapshot (the write outlived an app restart) rollback falls back to invalidating `/me` and the item.
- `useRateMutation(itemId)` reads a `RatingQueue` (`cache`, `enqueue`, `drain`) from `RatingQueueProvider`. P5.B.2.3 builds it in `auth/runtime.ts`: the store, the drain with `onResult: cache.onResult` plus toasts, and `enqueue` bound to the `/me` user.
- The item aggregate is only touched as `ratingCount` (+1/-1) optimistically. The score cannot be computed on the client (the formula and priors live on the server), so it waits for the server body.

## Risks / follow-ups

- Gap against the ROADMAP acceptance: "`accessibilityValue.now` is 13 for 6.5". `RatingInput` sends `{min: 0, max: 10, now: 6.5}`. React Native types `now` as an integer, so Android TalkBack may truncate it. The fix belongs in `src/ui/RatingInput.tsx`, which impl-mobile rows lock, so I did not touch it. New row FIX-mobile-rating-a11y-now (impl-mobile): send `{min: 1, max: 20, now: value * 2}` and keep `text` for the spoken value.
- 32 dp stars with 6 dp hit slop, and wrapping below 360 dp: these are layout facts of `RatingInput` (44 px row, flex stars), so they are impl-mobile's call.
- The queue is not wired at runtime yet. That is P5.B.2.3.
