# Changelog rules

- Keep a Changelog 1.1.0, SemVer tags `vX.Y.Z`. Release sections are generated by git-cliff (`.config/cliff.toml`, P1.A.2.2) from Conventional Commits (ADR 0013).
- `[Unreleased]` is edited by hand only before a release, with Added/Changed/Fixed/Removed groups (AGENTS.md "Rules"). Otherwise write a good commit message: `feat` → Added, `fix` → Fixed, `refactor`/`perf` → Changed; `docs`/`test`/`ci`/`build`/`chore` stay out.
- Releasing: `git cliff --config .config/cliff.toml --tag vX.Y.Z -o CHANGELOG.md`, commit `chore(release): vX.Y.Z`, annotated tag `vX.Y.Z` on `main`, push the commit and the tag. The GitHub release is published from that section.
- Push version tags one at a time. GitHub creates no push event when more than three tags go up in a single push, so the release workflow never runs for them. For a tag already pushed without a release, publish it with `gh release create vX.Y.Z --verify-tag --notes-file <section>`, or re-run the release workflow with `workflow_dispatch`.
- Never move a pushed tag.
